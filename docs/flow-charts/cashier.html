Cashier · Flowchart

Cashier — online pickup queue

One tap per online order on the happy path: Mark served. Proof auto-verifies; only an amount/ref mismatch flags. Every tap is status-guarded — a stale or duplicate tap is a friendly no-op. Counter tasks are in cashier-counter.html.

Spec

Sign in
Google, own staff account, /cashier role-guarded; role read per request; the header names the cashier on duty; Switch account = sign out → sign in; every tap stamped handledBy.
Online pickup queue
Prepaid, no tender to settle. Order code shown; screenshot auto-verified. Flag = amount/ref mismatch → Approve / Reject. Recently-verified list for at-leisure spot-check; awaiting-proof row shows in-window orders with no screenshot.
Recently-verified list
At-leisure spot-check, no quota. Reject stays reachable until Mark served (the reject-after-the-fact path).
Approve or Reject?
Approve → Mark served. Reject → its own state: rejection record + image kept 7 days; refund owed = entered amount, claimed; ticket leaves NOW; tracker reads “needs checking”.
Undo / Void
Approve (undo) → ticket rejoins NOW by age, timer never restarted, no NEW badge. Void → refund owed survives until admin Mark refunded.
Mark served
The one happy-path tap: writes the sale to sales/{id}; kitchen ticket clears; tracker flips READY.
Ready — awaiting handover
Server clears the ticket off NOW at ready-for + 15 min or at close. Counter row, zero taps. Still uncollected at close → Unclaimed (money kept, manual note, counts as revenue). Customer returns with code → Collect late, no second sale write.
Dismissed list
Zero proof at 15:00 → the order is dismissed automatically. Restore re-arms the 15-minute window and writes an audit entry; Void is also available.
Status guard
Every tap is status-guarded: a stale or duplicate tap is a friendly no-op.
