Customer — payment to collection

GCash proof auto-verifies; only an amount/ref mismatch flags. The tracker is session/account-bound — the order code is shown, never typed. The ordering path is in customer-ordering.html.

Spec

Order tracker
Live status screen, session/account-bound. The order code is shown, never typed; reopen from the account with zero typing. 5–10 s poll: awaiting payment → verifying → cooking → READY.
Pay GCash → Attach
OS screenshot, newest thumbnail, auto-uploads. Failed → “Upload failed — tap to retry”; amount (prefilled) + ref#.
Auto-verified?
Amount + ref match → the kitchen ticket appears the same instant. Mismatch or blank ref → flagged hold.
Kitchen ticket
Order code + age timer. Scheduled pickup: dimmed in LATER, promoted at pickup − 15 min.
Flagged hold
The kitchen waits; both numbers shown side by side; the cashier makes a one-tap Approve / Reject.
Payment rejected
Tracker: “Payment needs checking — see the counter”; entered amount + order total shown; ticket off the board; refund owed (claimed). Cashier Approve (undo) → the ticket rejoins by age.
Voided
Cashier Void → refund owed survives until admin Mark refunded.
Dismissed
deadlineAt reached with zero proof and not mid-upload → tracker flips: “Order dismissed — no payment received”; queue auto-clears into the Dismissed list.
Restored
Cashier Restore re-arms the 15-minute window; the tracker flips back to awaiting payment; the customer re-attaches the same screenshot.
Cooked → Mark served
Cashier marks served; the tracker flips cooking → READY the same instant; collect with order code; feeds analytics.
Unclaimed
Paid but never collected at close — money kept, counts as revenue. Returns with code → cashier Collect late.
Void from Dismissed
Void is also reachable from the Dismissed list — see the cashier chart (cashier.html).
