Kitchen · Flowchart

Kitchen board

Read-only by design: zero input, zero login, zero cook interaction. The server owns lanes, promotion, and expiry — the cook owns nothing.

Spec

Open /kitchen
Reached via a secret URL — no login, kiosk-level access.
Ticket board
Two lanes. NOW and LATER.
NOW
Oldest first. Shows order code and age timer (red at 12 min). Walk-ins enter at settle with their code. NEW tickets flash ~5 s, badge until age 3 min. All-day = NOW only.
LATER
Scheduled pickups, full-size dimmed rows, ready-for + countdown.
Promotion
The server promotes LATER → NOW at pickup − 15 min or at verify (whichever is later); both clocks run, LATE immediately if overdue.
Board poll
Fixed 5 s fetch + heartbeat; stale >15 s shows “Reconnecting…” and auto-reloads. Verified, unserved orders only.
Mark served
Cashier marks an order served → ticket leaves NOW.
Reject proof
Cashier rejects a proof → ticket leaves NOW instantly (the board mirrors verified, unserved orders).
Approve rejected proof
Cashier approves a rejected proof → ticket rejoins NOW by age; timer never restarted.
Ready-for + 15 min
Any NOW ticket at ready-for + 15 min or at close: the server clears it off the board → cashier ready-awaiting-handover row.
Cook rule
The cook never touches the board: no editing, no statuses, no session.

Cashier · Flowchart

Cashier — online pickup queue

One tap per online order on the happy path: Mark served. Proof auto-verifies; only an amount/ref mismatch flags. Every tap is status-guarded — a stale or duplicate tap is a friendly no-op. Counter tasks are in cashier-counter.html.

Spec

Sign in
Google, own staff account, /cashier role-guarded; role read per request; the header names the cashier on duty; Switch account = sign out → sign in; every tap stamped handledBy.
Online pickup queue
Prepaid, no tender to settle. Order code shown; screenshot auto-verified. Flag = amount/ref mismatch → Approve / Reject. Recently-verified list for at-leisure spot-check; awaiting-proof row shows in-window orders with no screenshot.
Recently-verified list
At-leisure spot-check, no quota. Reject stays reachable until Mark served (the reject-after-the-fact path).
Approve or Reject?
Approve → Mark served. Reject → its own state: rejection record + image kept 7 days; refund owed = entered amount, claimed; ticket leaves NOW; tracker reads “needs checking”.
Undo / Void
Approve (undo) → ticket rejoins NOW by age, timer never restarted, no NEW badge. Void → refund owed survives until admin Mark refunded.
Mark served
The one happy-path tap: writes the sale to sales/{id}; kitchen ticket clears; tracker flips READY.
Ready — awaiting handover
Server clears the ticket off NOW at ready-for + 15 min or at close. Counter row, zero taps. Still uncollected at close → Unclaimed (money kept, manual note, counts as revenue). Customer returns with code → Collect late, no second sale write.
Dismissed list
Zero proof at 15:00 → the order is dismissed automatically. Restore re-arms the 15-minute window and writes an audit entry; Void is also available.
Status guard
Every tap is status-guarded: a stale or duplicate tap is a friendly no-op.

Cashier · Flowchart

Cashier — counter tasks

Walk-in ring-up, reservations, and rentals. The online pickup queue has its own chart: cashier.html. Every tap is status-guarded: a stale or duplicate tap is a friendly no-op.

Spec

Walk-in ring-up
Tap product tiles; the menu search narrows the tiles to a matching name; each tile lists its add-ons, and ticked add-on prices join the line total; promo price + totals compute; order code drawn at ring-up (on the receipt); optional table name printed on the receipt.
Settle
Type the cash handed — one number. cash ≥ total → all-cash + change computes; cash < total → GCash = total − cash, ref# required. Σ(payments) = total asserted.
Receipt
One button; the order code is printed.
Kitchen ticket
The ticket appears at settle in the NOW lane with its order code and age timer.
Mark served
Writes the sale, clears the kitchen ticket, flips the tracker READY. The one happy-path tap.
New reservation
Type the phone; typeahead prefills name / party / preferred type. Returning: phone → date/time → confirm (≤3 inputs); new customer: 2 steps (≤3 + ≤2). Dine-in / function room / catering.
Conflict check
Date-time conflict or duplicate → Blocked with a reason, nothing written. Otherwise stored pending → calendar/list, with confirmed · cancelled statuses shown. Confirm re-checks against fresh data on the server.
Rentals
Hand over → stock falls; Confirm return → stock rises. Flagged proof: one-tap Confirm / Cancel (stock untouched). Overdue = quiet staff row, no auto-penalty.
Status guard
Every tap is status-guarded: a stale or duplicate tap is a friendly no-op.

Admin · Flowchart

Admin console

One role-guarded account branches into five areas: dashboard, catalog, staff, settings, and reports. Everything reads the one RTDB stream.

Spec

Sign in
Admin account at /admin, role-guarded.
Dashboard
KPIs, monthly GCash/cash mix, 7-day trend, best-sellers, peak hours, refunds-owed badge.
Products + inventory
Add/edit product + image (server resize → base64 in RTDB); categories + per-product add-ons; one-click promo (% or ₱ → computed label); hide toggle = 86 (no food stock); inventory = rental units with −/+ steppers and Add stock (supplier · qty · date), low-stock flags, restock button; rental items CRUD (name · image · price/day · units).
Staff accounts
Create / demote / delete (name + Google email · Google-only, no passwords). Each evicts the cached role. No public signup.
Settings
Hours per weekday + force-close + scheduled date-range closures → public open/closed badge; announcement banner; GCash number + QR upload (both required before ordering opens); rotate kitchen secret; reservation capacities (smart default); Complete setup banner until the payment block exists.
Reports
Sales · reservations · rental bookings with date filters; refunds owed → Mark refunded; Activity (time · who · action · order code); per-cashier totals (handledBy); scheduled incremental export (by updatedAt).
One RTDB stream
The dashboard reads the one RTDB stream (online + counter orders).

Customer · Flowchart

Customer — browse to order

Browse is open to everyone; ordering requires Sign in with Google. Online orders are pickup-only, GCash-only, identified by order code. Payment is in customer-payment.html; rentals and the read-only views are in customer-rentals.html.

Spec

Browse
Open to everyone — the menu is visible with no login wall. Filter by tapping a category chip.
Open?
Hours + force-close + scheduled closures + GCash number & QR configured. Closed or setup incomplete → read-only: menu + announcement, place-order disabled with a plain reason (admin sees “Complete setup”). Open → the menu.
Menu
Grouped by category, promo / Top 3 tags, computed prices, served from the catalog cache (no image re-read per view).
Product page
Add to cart with steppers, add-ons, and computed totals.
Per-account prefs
Favorites and the last add-on selection save to users/{uid} and sync across devices; the last pick is pre-checked in the cart.
Cart
Inline steppers + add-on picks; last pick pre-checked from users/{uid}; totals recompute server-side.
Sign in
Sign in with Google — one tap, session remembered.
Checkout
Pickup time, default ASAP; earliest = now + 15 min.
Place order
POST to Laravel: validated, throttled, idempotency key. Returns the order code + GCash number + QR; the 15-minute payment window (deadlineAt) starts.

Customer · Flowchart

Customer — payment to collection

GCash proof auto-verifies; only an amount/ref mismatch flags. The tracker is session/account-bound — the order code is shown, never typed. The ordering path is in customer-ordering.html.

Spec

Order tracker
Live status screen, session/account-bound. The order code is shown, never typed; reopen from the account with zero typing. 5–10 s poll: awaiting payment → verifying → cooking → READY.
Pay GCash → Attach
OS screenshot, newest thumbnail, auto-uploads. Failed → “Upload failed — tap to retry”; amount (prefilled) + ref#.
Auto-verified?
Amount + ref match → the kitchen ticket appears the same instant. Mismatch or blank ref → flagged hold.
Kitchen ticket
Order code + age timer. Scheduled pickup: dimmed in LATER, promoted at pickup − 15 min.
Flagged hold
The kitchen waits; both numbers shown side by side; the cashier makes a one-tap Approve / Reject.
Payment rejected
Tracker: “Payment needs checking — see the counter”; entered amount + order total shown; ticket off the board; refund owed (claimed). Cashier Approve (undo) → the ticket rejoins by age.
Voided
Cashier Void → refund owed survives until admin Mark refunded.
Dismissed
deadlineAt reached with zero proof and not mid-upload → tracker flips: “Order dismissed — no payment received”; queue auto-clears into the Dismissed list.
Restored
Cashier Restore re-arms the 15-minute window; the tracker flips back to awaiting payment; the customer re-attaches the same screenshot.
Cooked → Mark served
Cashier marks served; the tracker flips cooking → READY the same instant; collect with order code; feeds analytics.
Unclaimed
Paid but never collected at close — money kept, counts as revenue. Returns with code → cashier Collect late.
Void from Dismissed
Void is also reachable from the Dismissed list — see the cashier chart (cashier.html).

Customer · Flowchart

Customer — reservations & rentals

Two read-first paths off the menu: the occupancy view books nothing, and the rental catalog books through the same GCash gate as orders. The ordering path is in customer-ordering.html.

Spec

About / branches page
Reachable from arrival, alongside the menu.
Public occupancy view
Read-only: seats taken vs capacity per slot, no names, books nothing.
Rental catalog
Read-only: price/day and computed per-date availability.
Book
Date range + qty steppers; the total computes → sign in → QR auto-sent. Prepaid with a 15-minute window; unpaid lapses. Proof flag (amount/ref mismatch) → counter, one-tap Confirm / Cancel.
Counter handover
Handover → stock falls; return by due date → stock rises.
