# Category Filter & Email Receipt — Implementation Plan

> **For Hermes:** Two independent features, one afternoon of work.

**Goal:** Add category-filter tabs on user/cashier product pages, and wire the existing `sendOrderReceipt()` to fire when cashier marks an order paid.

**Architecture:** Client-side JS filter (show/hide by `data-cat`) + one PHP call in the existing `mark_paid` handler. Uses the already-built `mailer.php::sendOrderReceipt()` — zero new infrastructure.

**Tech Stack:** PHP 8.5, Firebase RTDB, PHPMailer (existing), vanilla JS.

## Task 1: Category filter tabs — cashier POS

**Objective:** Add clickable category tabs above `.pos-grid` that show only matching products. "All" tab shows everything.

**Files:**
- Modify: `cashier/order_now.php`

**Step 1: PHP — collect unique categories**

Before the product loop (around line 255), extract all unique categories from products:

```php
$cats = [];
foreach ($products as $p) {
    if (!empty($p['category'])) {
        $cats[$p['category']] = true;
    }
}
ksort($cats); // alphabetical
```

**Step 2: HTML — render tabs**

Above `.pos-grid`:

```php
<div class="pos-cats" id="posCats">
  <button class="pos-cat is-active" data-cat="">All</button>
  <?php foreach (array_keys($cats) as $c): ?>
    <button class="pos-cat" data-cat="<?= e($c) ?>"><?= e($c) ?></button>
  <?php endforeach; ?>
</div>
```

**Step 3: CSS — pill-shaped tabs**

```css
.pos-cats { display:flex; gap:6px; flex-wrap:wrap; margin-bottom:12px; }
.pos-cat { font-size:12px; font-weight:600; padding:4px 12px; border-radius:999px;
  border:1px solid var(--line,#e6dfd1); background:var(--surface,#fff);
  cursor:pointer; color:var(--muted); transition:.15s; }
.pos-cat.is-active { background:var(--ink,#211b14); color:#fff; border-color:var(--ink); }
.pos-cat:hover { border-color:var(--ink); color:var(--ink); }
.pos-cat.is-active:hover { color:#fff; }
```

**Step 4: JS — filter on click**

One event listener on `posCats` container (delegation):

```js
document.getElementById('posCats')?.addEventListener('click', function(e) {
  var btn = e.target.closest('.pos-cat');
  if (!btn) return;
  this.querySelector('.is-active')?.classList.remove('is-active');
  btn.classList.add('is-active');
  var cat = btn.dataset.cat;
  document.querySelectorAll('#posGrid .pos-item').forEach(function(el) {
    el.style.display = !cat || el.dataset.cat === cat ? '' : 'none';
  });
});
```

**Verification:** Click a category tab → only products in that category visible. Click "All" → all products show. Tab with no products shows nothing (correct).

## Task 3: Email receipt on mark_paid

**Objective:** When a cashier marks an order as paid, send the receipt to the customer's email (if they have one, i.e. not "walk-in").

**Files:**
- Modify: `cashier/index.php:92-99`

**Step 1: One-line require + two-line guard and send**

In the `mark_paid` branch, after the `flash()` call (line 99), add:

```php
require_once __DIR__ . '/../mailer.php';
$email = $order['user_email'] ?? '';
if ($email !== '' && $email !== 'walk-in') {
    sendOrderReceipt($email, $order);
}
```

That's it. The `$order` variable already holds the full order array (line 59: `$order = $db->retrieve(...)`) with all keys `sendOrderReceipt()` expects: `id`, `items`, `total`, `full_name`, `payment_method`, `payment_status`, `created_at`, `pickup_time`.

**Existing data mapping check:**

| `sendOrderReceipt()` param | Order key in DB | Status |
|---|---|---|
| `$order['id']` | Not in fetched array; the order ID is `$orderId` | **Fix needed** — pass `$orderId` or add it to the array before calling |
| `$order['items']` | `items` (array of {name,qty,price,subtotal}) | ✓ |
| `$order['total']` | `total` | ✓ |
| `$order['full_name']` | `customer_name` or `full_name` | User orders have `full_name`; cashier walk-in orders have `customer_name`. The mailer reads `full_name`. **Fix:** normalize before calling: `$order['full_name'] = $order['full_name'] ?? $order['customer_name'] ?? '';` |
| `$order['payment_method']` | `payment_method` | ✓ |
| `$order['payment_status']` | `payment_status` | ✓ |
| `$order['created_at']` | `created_at` or `placed_at` | ✓ (`created_at` from cashier, `placed_at` from user) |
| `$order['pickup_time']` | `pickup_time` | ✓ (set on user checkout, may be empty for walk-in) |

**Step 2: Final code**

```php
} elseif ($action === 'mark_paid' && ($order['payment_status'] ?? '') !== 'paid') {
    $db->update('/orders', $orderId, [
        'payment_verified' => true,
        'payment_status'   => 'paid',
        'verified_at'      => now(),
        'verified_by'      => $cashierName,
    ]);
    flash('Order #' . $short . ' marked as paid.', 'ok');
    // Send receipt email if this order has a real email
    $email = $order['user_email'] ?? '';
    if ($email !== '' && $email !== 'walk-in') {
        $order['id'] = $orderId;
        $order['full_name'] = $order['full_name'] ?? $order['customer_name'] ?? '';
        require_once __DIR__ . '/../mailer.php';
        sendOrderReceipt($email, $order);
    }
}
```

**Step 3: Verify**

1. Create a user order (via checkout) that goes to `pending_verification` payment
2. Cashier marks it paid → receipt email sent
3. Walk-in order marked paid → no email sent (email = 'walk-in')
4. `mailer.php` `sendMail()` returns false → logged to error_log, no user-visible error (existing behavior)

## Risks & Open Questions

- **Category field might be empty** on old products — they're hidden from tabs (must have a non-empty string to appear). The PHP `ksort` handles this.
- **No categories at all** → only "All" tab appears. The filter loop shows everything. Correct.
- **Email send failure** silently logs to error_log (existing `sendMail()` behavior). No flash message to confuse the cashier.
- **sendOrderReceipt expects `order['id']`** — the fetched order doesn't include the Firebase key as an `id` field. The fix above adds it.
- **Walk-in orders have `customer_name` not `full_name`** — the fix normalizes this before calling `sendOrderReceipt()`. The mailer uses `full_name` for the greeting; empty falls back to "Hi there,".
