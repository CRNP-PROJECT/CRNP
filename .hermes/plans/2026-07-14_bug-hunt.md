$fileType = strtolower(pathinfo($targetFile, PATHINFO_EXTENSION));

#### Task 2: Fix no SSL cert verification on Firebase

**Files:** Modify `firebaseRDB.php:25`

**Bug:** `CURLOPT_SSL_VERIFYPEER => false` — all Firebase traffic is vulnerable to MITM. Should be `true` for production.

```php
// Before:
curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, false);
// After:
curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, true);
```

**Risk:** If the system CA bundle is missing, curl will fail. Keep previous value as fallback if test shows breakage.  
**Verify:** `php -l firebaseRDB.php`. Then run a known-working page (e.g. `user/login.php` renders 200).

#### Task 3: Add auth guards to cashier process

**Files:** Modify `cashier/cashier_process.php`

**Bug:** Every action method (`cancelOrder`, `updateStatus`, `markPaid`, `markNotPaid`, `updateBookingStatus`, `markBookingPaid`) has **zero session auth checks**. Any POST to `cashier_process.php` modifies orders/bookings.

**Fix:** Add one guard at the top of `handle()`, before the switch:

```php
public function handle()
{
    // Guard all actions except login/logout
    if (!isset($_SESSION['cashier_email']) && $this->action !== 'login') {
        header("Location: cashier_login.php");
        exit;
    }
    // ... switch ...
}
```

**Verify:** POST `action=update_status&order_id=xxx&status=paid` without session → 302 to login.

#### Task 4: Add session regeneration after login

**Files:** Modify `user/login_action.php`, `kitchen/kitchen_process.php`, `cashier/cashier_process.php`

**Bug:** After `password_verify()` succeeds, no `session_regenerate_id(true)`. Session fixation attack — attacker sets a known session ID, victim logs in, attacker shares same session.

**Fix:** Add `session_regenerate_id(true);` immediately after each successful password verify, before setting session vars.

**Verify:** Login, check `session_id()` changes. (One request before login, one after — different.)

### Phase 2: Edge cases & exception hardening

#### Task 5: Handle Firebase curl failures gracefully

**Files:** Modify `firebaseRDB.php:grab()`

**Bug:** `curl_exec` returns `false` on failure (network, timeout). Callers `json_decode(false, true)` → NULL. Accessing NULL as array → PHP 8.1+ deprecation.

**Fix:** Wrap grab output:

```php
$html = curl_exec($ch);
if ($html === false) {
    error_log("Firebase curl error: " . curl_error($ch));
    return json_encode([]); // or '{}' 
}
return $html;
```

**Verify:** `php -l firebaseRDB.php`. Hard to test without killing network, but syntax is clean.

#### Task 6: Deduplicate stock-restore logic

**Files:** Modify `user/process.php`, `cashier/cashier_process.php`

**Bug:** The rent-item stock restore loop (iterate booking items → match by name → increment quantity) is copy-pasted identically in:
- `user/process.php:cancelBooking()` lines 116-153
- `cashier/cashier_process.php:updateBookingStatus()` lines 272-308

**Fix:** Extract to a standalone helper function. Add to `firebaseRDB.php` or as a new utility:

```php
function restoreRentStock($firebase, $items) {
    if (empty($items) || !is_array($items)) return;
    $rent_items = json_decode($firebase->retrieve("/rent_items"), true) ?? [];
    foreach ($items as $item) {
        $qty = intval($item['qty'] ?? 0);
        $name = strtolower(trim($item['name'] ?? ''));
        if ($qty <= 0 || $name === '') continue;
        foreach ($rent_items as $rid => $ritem) {
            if (strtolower(trim($ritem['name'] ?? '')) === $name) {
                $firebase->update("/rent_items", $rid, [
                    "quantity" => intval($ritem['quantity'] ?? 0) + $qty
                ]);
                break;
            }
        }
    }
}
```

Replace both copies with one call: `restoreRentStock($this->rdb, $booking['items']);`

**Verify:** `php -l user/process.php && php -l cashier/cashier_process.php`.
